# Generator-Aware Positive Row Scaling for Block-Structured Engineering MIPs

Reproducibility repository for the paper *“Generator-Aware Positive Row Scaling for
Block-Structured Engineering Mixed-Integer Programs”* (International Journal for Numerical
Methods in Engineering, free-format submission).

The paper studies **generator-aware positive row scaling**: a model generator uses its
pre-export block/coupling structure to choose strictly positive row factors that improve
the solver-facing numerical representation **without changing the mixed-integer program**.
Two generator-aware variants (`SA-Aug`, `SA-Mat`) are compared with the unscaled model and
Ruiz-type baselines, on a hydrothermal-dispatch testbed (three instance classes, two
commercial solvers, two MIP gaps) and on a controlled synthetic block-structured benchmark.

> The released C++ code is a cleaned reproducibility version containing the monolithic MIP
> path and preprocessing methods used in the paper. Experimental aggregate outputs are
> provided from the original ClusterUY runs.

The neural-network (LSTM) and Dantzig–Wolfe / column-generation code of the broader research
project is **not** part of this repository.

## Naming map (paper ↔ code)

The code and `resumen.csv` use Spanish slugs; the paper uses English names.

| Paper variant | Code slug                | `PreprocesamientoMIP::Config` |
|---------------|--------------------------|-------------------------------|
| Base          | `base`                   | no scaling |
| SA-Aug        | `estructurado`           | `escalamientoLocalPorFila + normalizarBloqueTrasFilas` |
| SA-Mat        | `estructurado_matricial` | SA-Aug + `modoMatricial` |
| Ruiz          | `ruiz`                   | `usarEquilibradoRuiz + escalamientoLocalPorFila + normalizarBloqueTrasFilas` |
| Ruiz+Cols     | `ruiz_columnas`          | Ruiz + `escalarColumnasContinuas + normalizacionFisica` |

## Reproduction levels

### N0 — tables and figures, no solver (minutes)
Rebuilds every dispatch table/figure from the in-tree `results/*/resumen.csv`:
```bash
make analysis-n0          # outputs under results-analysis/
```
Needs only Python (`environment/python-requirements.txt`).

### N1 — synthetic benchmark, license-free (Cbc)
Builds with the open-source Cbc solver (no commercial license) and runs the synthetic
mechanism check:
```bash
make synthetic-mini
# equivalently, the license-free build:
#   make -C code USE_GUROBI=0 USE_CPLEX=0 USE_CBC=1 USE_HEXALY=0
```
The full synthetic grid that produces the paper’s synthetic figures (`paper/figs/fig*.pdf`)
is generated by running `code/build/SistemaElectrico < data/synthetic/grilla_inicial_gurobi.txt`
and post-processing with `scripts/analizar_grilla_sintetica.py`.

### N2 — full dispatch runs, commercial solvers (hours–days)
Reproduces the `resumen.csv` from scratch with Gurobi/CPLEX:
```bash
cd code && make                 # Gurobi + CPLEX + Cbc
cd ..
python3 scripts/validar_preprocesamiento.py \
    data/entradas/entrada-modelo-simple \
    --exe code/build/SistemaElectrico --solver Gurobi \
    --timeout 3600 --mipgap 0.01 \
    --variantes base,estructurado,estructurado_matricial,ruiz,ruiz_columnas \
    --output results/validacion-preproc-simple --verificar-original
```
This is long; the Full class is the slowest. SLURM templates for a cluster are in
`cluster/`. To re-derive `resumen.csv` from the raw solver logs only (no solving),
download the external logs archive (see `artifacts/README.md`) and run
`scripts/reparsear_resumen.py results/<scenario>`.

### N3 — build the paper PDF
```bash
make paper                # paper/main.pdf (needs TeX Live + elsarticle)
```

## Build and environment

- `cd code && make USE_HEXALY=0` — Gurobi + CPLEX + Cbc (set `GUROBI_HOME` / `CPLEX_HOME`).
- License-free: `make -C code USE_GUROBI=0 USE_CPLEX=0 USE_CBC=1 USE_HEXALY=0`.
- Toolchain and solver versions: `environment/solver-notes.md`. Smoke tests and a model
  fingerprint: `code/SMOKE.md`.

## Sanity check before publishing
```bash
make sanity-check         # scans for leaked paths/secrets and residual LSTM/DW symbols
```
