# Structure-Aware Row Scaling for Block-Structured Mixed-Integer Programs

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.20648950.svg)](https://doi.org/10.5281/zenodo.20648950)

Reproducibility repository for the paper *“Structure-Aware Row Scaling for
Block-Structured Mixed-Integer Programs”* (International Journal for Numerical
Methods in Engineering).

The paper studies **structure-aware positive row scaling**: a model generator uses its
pre-export block/coupling structure to choose strictly positive row factors that improve
the solver-facing numerical representation **without changing the mixed-integer program**.
Two structure-aware variants (`SA-Aug`, `SA-Mat`) are compared with the unscaled model and
Ruiz-type baselines, on a hydrothermal-dispatch testbed (three instance classes, two
commercial solvers, two MIP gaps) and on a controlled synthetic block-structured benchmark.

> The released C++ code is a cleaned reproducibility version containing the monolithic MIP
> path and preprocessing methods used in the paper. Experimental aggregate outputs are
> provided from the original ClusterUY runs.

The neural-network (LSTM) and Dantzig–Wolfe / column-generation code of the broader research
project is **not** part of this repository.

## Reproduction levels

### N0 — tables and figures, no solver (minutes)
Rebuilds every dispatch table/figure from the in-tree `results/*/resumen.csv`:
```bash
make analysis-n0          # outputs under results-analysis/
```
Needs only Python (`environment/python-requirements.txt`).

### N1 — synthetic benchmark, license-free (Cbc)
Builds with the open-source Cbc solver (no commercial license) and runs the synthetic
mechanism check. The target always compiles its own license-free binary into
`code/build-cbc/`, so it never depends on a preexisting Gurobi/CPLEX build:
```bash
make synthetic-mini
# equivalently, the license-free build:
#   make -C code BUILD_DIR=build-cbc USE_GUROBI=0 USE_CPLEX=0 USE_CBC=1 USE_HEXALY=0
```
The mini synthetic benchmark is license-free and uses Cbc. The full synthetic grid
used for the paper figures follows the solver configuration encoded in its grid
file; the file name `grilla_inicial_gurobi.txt` indicates the Gurobi-based run used
for the manuscript. That full grid is generated by running
`code/build/SistemaElectrico < data/synthetic/grilla_inicial_gurobi.txt` (Gurobi build)
and post-processing with `scripts/analizar_grilla_sintetica.py`; its outputs are the
paper's synthetic figures, included at
`paper/synthetic/resultados/grilla_inicial_gurobi/paper_exports/fig*.pdf` (the path the
manuscript references through `\graphicspath`).

### N2 — full dispatch runs, commercial solvers (hours–days)
Reproduces the `resumen.csv` from scratch with Gurobi/CPLEX:
```bash
cd code && make                 # Gurobi + CPLEX + Cbc
cd ..
python3 scripts/validar_preprocesamiento.py \
    data/entradas/entrada-modelo-simple \
    --exe code/build/SistemaElectrico --solver Gurobi \
    --timeout 3600 --mipgap 0.01 \
    --variantes base,estructurado,estructurado_matricial,ruiz,ruiz_columnas \
    --output results/validacion-preproc-simple --verificar-original
```
This is long; the Full class is the slowest. SLURM templates for a cluster are in
`cluster/`. To re-derive `resumen.csv` from the raw solver logs only (no solving),
download the external logs archive (see `artifacts/README.md`) and run
`scripts/reparsear_resumen.py results/<scenario>`.

### N3 — build the paper PDF
```bash
make paper                # paper/main.pdf (needs XeLaTeX on TeX Live 2022 + Wiley NJD v5 class files)
```
The manuscript uses the Wiley New Journal Design v5 class (`WileyNJDv5.cls`, AMA style);
see `paper/README.md` for the class-file and font prerequisites.

## Build and environment

- `cd code && make USE_HEXALY=0` — Gurobi + CPLEX + Cbc (set `GUROBI_HOME` / `CPLEX_HOME`).
- License-free: `make -C code USE_GUROBI=0 USE_CPLEX=0 USE_CBC=1 USE_HEXALY=0`.
- Toolchain and solver versions: `environment/solver-notes.md`. Smoke tests and a model
  fingerprint: `code/SMOKE.md`.

## Sanity check before publishing
```bash
make sanity-check         # scans for leaked paths/secrets and residual LSTM/DW symbols
```

## Archiving and DOI (Zenodo)
This repository is archived on Zenodo through the GitHub–Zenodo integration, using the
metadata in `.zenodo.json`. Cite the **concept DOI**
[`10.5281/zenodo.20648950`](https://doi.org/10.5281/zenodo.20648950), which always
resolves to the latest archived version; each release also receives its own version DOI.

The heavy per-instance logs/CSVs (release assets, ~180 MB) are not part of the
auto-archived source tarball; attach them to the Zenodo record manually if a single
self-contained archive is desired. The journal-article DOI in `CITATION.cff`
(`preferred-citation`) remains `PENDING` until the paper is published.
