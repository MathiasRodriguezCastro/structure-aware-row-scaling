\section{Reproduction and artifact layout}
Online Resource~2 is the complete code/data package for
\path{v1.7.0-orf-submission}. It contains the unchanged scientific-evidence archive
\path{v1.3.17-oms-submission}, its validation record, the current ORF editable
sources and a checksum-based inheritance record. The older editorial files inside
the scientific archive identify its provenance; the current article and this
supplement are supplied in the ORF source bundle.

The separate \texttt{prospective-scenarios-orf-20261018.zip} adds 24 new parameter
scenarios, 360 primary MIP calls plus a 360-call logging confirmation, rational reference acquisition and their independent
checks. After extracting the inherited scientific archive, extract this ZIP
over the same root and run, without a commercial solver license:
\begin{lstlisting}
python3 exploration/orf-confirmatory-20261018/check.py
python3 exploration/orf-confirmatory-20261018/check.py --logging-confirmation
python3 exploration/orf-confirmatory-20261018/check_export_bound.py
python3 exploration/orf-confirmatory-20261018/check_cluster_analysis.py
python3 exploration/orf-confirmatory-20261018/parent_sensitivity.py --check
\end{lstlisting}
Its protocol distinguishes new generated scenarios from known parent data and
from an independent application. Native solver logs and every saved point are
retained. The rational certificates are reference points and lower bounds,
rather than certificates of every returned floating-point candidate.

The larger confirmation is supplied as a lossless archive. After extracting
its tar/xz file over the same root, run these saved-evidence checks:
\begin{lstlisting}
python3 exploration/orf-confirmatory-extension-20261019/seal_confirmation.py --check
python3 exploration/orf-confirmatory-extension-20261019/seal_pending_validation.py --check
python3 exploration/orf-confirmatory-extension-20261019/seal_reference_recovery.py --check
python3 exploration/orf-confirmatory-extension-20261019/verify_confirmation_analysis.py
\end{lstlisting}
The last command reconstructs 48 comparisons and 80 whole-parent intervals
from 480 saved block reports without optimization. The archive's per-file
inventory preserves all final-campaign, pilot and reference data. Its hard
links retain identical file contents at their original paths. Repeating every
full rational candidate audit is available through
\path{replay_confirmation.py} for block indices 0--479, with a substantially
larger replay cost. Reference and pilot acquisition remain separately costed.

The post hoc written-bound sensitivity is a separate, small payload inside
\path{orf-revision-sources.zip}. Extract those canonical sources over the same
root, then run:
\begin{lstlisting}
python3 scripts/research/orf_acceptance_sensitivity.py
python3 scripts/research/check_orf_acceptance_sensitivity.py
python3 scripts/research/orf_confirmation_tables.py
\end{lstlisting}
The checker reconstructs 13,387 candidate domain tests from saved vectors and
written bounds. Other acceptance checks reuse the sealed independent audits.
The zero threshold reproduces registered successes; alternative thresholds
change neither the primary endpoint nor its measured times. All seven current
confirmation table fragments regenerate from these supplied inputs.

Next extract \path{verified-candidates-orf-20261019.zip} over that same root.
Its \path{FOLLOWUP_CONTENTS.sha256} identifies the frozen follow-up files.
Run these six license-free commands from the extracted repository root:
\begin{lstlisting}
python3 exploration/orf-v15-verified-20261019/check.py
python3 exploration/orf-v15-verified-20261019/check_selector.py
python3 exploration/orf-v15-verified-20261019/precision.py
python3 exploration/orf-v15-verified-20261019/analyze.py
python3 exploration/orf-v15-verified-20261019/check_statistics.py
python3 exploration/orf-v15-verified-20261019/projection_sensitivity.py
\end{lstlisting}
These replay saved candidate vectors, exact export reserves, target attainment,
grouped uncertainty and the identified post hoc projection sensitivity. They
make no new commercial-solver calls. The separate package-validation record
identifies the exact inherited follow-up ZIP; canonical ORF sources supply the
table generator for the selected manuscript summaries.

Extract \texttt{scientific-evidence-oms-v1.3.17.zip} into an empty directory.
From its root, verify \texttt{CONTENTS.sha256}, install the dependencies in
\path{environment/research-requirements.txt}, and run:
\begin{lstlisting}
make research-oms-check
make research-check-python
make research-check
make research-analysis
\end{lstlisting}
These four commands are self-contained in the supplied archive. They check saved
results, exact witnesses, original-unit residuals, the native C++ exporter, named
bases and paired summaries, and regenerate all final tables and analysis figures.
No commercial optimizer license is required. The archive's
\path{paper/submission/oms/OMS_DATA_MANIFEST.json} inventories the additional
scientific inputs; \texttt{SNAPSHOT.json} identifies its version and campaigns.
The stopped-campaign screening tables use the supplied \texttt{runs.csv} and
\texttt{contradictions.csv}; they remain floating-point screening evidence.

The full native export check needs GNU Make and a C++17 compiler. Mathematical
tests include small SciPy reference linear programs. The figures are generated
with matplotlib from supplied data or explicit mathematical expressions.
SoPlex is only needed to generate fresh rational witnesses, rather than to check
those supplied. Recorded runtime is specific to the declared hardware and solver
versions; arithmetic replay does not recreate wall-clock measurements.

Reconstructing all 1,530 historical bases additionally requires
\texttt{fixed-basis-exports.tar.zst}, available with
\path{v1.2-coap-submission} at \url{https://doi.org/10.5281/zenodo.23145294}.
The separate archive contains 337 MB compressed and 5.18 GB uncompressed in
11,585 files. Its manifest and checksums are under
\path{paper/submission/data-deposit/} in the scientific archive. That bulk
reconstruction is not part of the four-command self-contained replay.

Extract the current \texttt{orf-editable-sources.zip} separately to rebuild the
submission documents:
\begin{lstlisting}
pdflatex main_orf
bibtex main_orf
pdflatex main_orf
pdflatex main_orf
pdflatex ESM_1
pdflatex ESM_1
\end{lstlisting}
The source bundle includes the publisher's class and bibliography style, all
figures, shared proofs and numerical tables. It builds the current ORF documents;
the historical scientific archive preserves the preceding OMS build recipe.

Optional fresh experiments are documented in the scientific archive's README and
write to separate output directories. Commercial-solver arms require the
corresponding licenses. The prospective study records its additional calls
separately. The current snapshot has no separate Zenodo version DOI.
